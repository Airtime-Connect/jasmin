The proposed workflow checks out the PR head, builds AMD64 with a revision label, tests imports, saves a gzip archive and SHA-256 receipt, reloads and retests, then uploads a seven-day artifact without publishing it. A local AMD64 Docker build from #12 with the final context exclusions passed C2 imports and absence checks for `/build/.git`, `/build/.env` and `/build/.specify`. Its compressed archive was 144 MB with SHA-256 `eac2f34df4b7f4fa92d4d3ccfe239a518947f4e920a80e3da279b4c168505a38`; reloading yielded the same local image ID `sha256:929f7936b19dcb24968436b5552e67d8a87c3499dfaef47643eccaf7865f883c` and passed C2 imports again. An earlier local build from the same source had a different image ID, so these receipts must not be treated as proof of bit-for-bit reproducibility. The local IDs do not identify the future CI artifact or deployed target.

This candidate process does not prove sovereign registry custody, target deployment, peer authentication, AMQP ACL or live egress. Test Hub remains NO-GO.

Follow-up review found that the candidate Dockerfile binds jCLI to `0.0.0.0` and ships the default admin identity and digest. The C2-required daemon path now checks effective `JCliConfig` authentication before loading the authority or opening listeners: disabled auth, shipped username, and shipped password digest each fail closed. This is a startup guard, not evidence of actual target credentials or network access control. The target operator still must attest approved non-default credentials and management ACL before deployment.

Entrypoint review found it launches `interceptord` in a separate process before `jasmind`; its PB also has shipped credentials and accepts serialized routables. The C2-required interceptor daemon now checks effective PB authentication in its constructor, before its listener. The main daemon checks router PB, SMPP client PB, optional SMPP server PB, optional jCLI, and optional interceptor PB before loading C2 authority or opening its listeners. These checks reject disabled authentication and shipped username or digest, while target config and network ACL remain unproven.

The image entrypoint now performs the main daemon's C2 config and authority validation before it starts the separate interceptor process, and suppresses exception text on failure. `jasmind` validates again in its own process. This makes startup validation read the authority twice; the sovereign factory's preflight is read-only, but target timing and process lifecycle still require a separate deployment receipt.

A further C2 management review found that the preflight accepted an empty username, empty or malformed digest, MD5 of the empty password, and a shipped default digest copied from another management surface. A focused red test produced 33 failures across five checks. The shared preflight now requires an exact enabled boolean, a nonblank unpadded username, a 16-byte digest, and excludes all shipped usernames/digests plus the empty-password digest. The jCLI daemon path also tests empty digest rejection before factory creation or listener startup. Local C2 suite passed 86/86. This is a candidate configuration guard; it does not validate target vault values or network ACL.

The effective `AmqpConfig` still defaulted to `guest/guest` while C2 startup checked only PB/jCLI authentication. A focused daemon regression first failed because the C2 authority factory was reached with the default broker identity. The C2 preflight now rejects either `guest` component and blank/padded broker credentials before factory/listeners. A local AMD64 image ran 83 C2 tests with no skips, rejected its packaged default AMQP identity, and proved synthetic non-default AMQP credentials reach the expected redacted sovereign-factory failure before any child starts. Target broker principal/vhost inventory and topic ACL remain separate release evidence.

This limits the candidate reader's Test Hub schema grants, not the target role's uninspected memberships or full RLS policy.

This is candidate SQL and local evidence; target role identity, membership, grants and RLS still need independent attestation.
