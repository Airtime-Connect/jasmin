# Convergence

The current PB avatar blocks protected `submit_sm` but its generic `__getattr__` delegated all connector mutators. `perspective_connector_remove`, `start` and `stop` take a CID; `connector_add` takes pickle bytes, while `load` and `stopall` can affect many connectors. The C2-active facade now refuses reserved-CID mutations after fresh authoritative classification, denies lookup ambiguity/outage, and refuses unbounded add/load/stopall without unpickling remote input. Commercial CID-targeted mutations and C2-inactive legacy behavior still delegate. Trusted in-process manager calls are unchanged.

Local Python 3.12 declared dependencies: `ci/run_testhub_c2.py` discovered and ran 68/68 with zero skips/failures/errors. A real loopback PB login/dispatch suite ran 4/4, covering protected and bulk denial, classifier outage, commercial delegation and legacy mode. No broker, SMSC, target route or production system was used. The C2-required deployment needs a separate authenticated, audited connector management path; target connector identity, broker ACL, image, inventory and live egress gates remain open.

Follow-up review found `perspective_connector_config` returns `pickle.dumps(connector['config'])` and a synthetic `SMPPClientConfig` pickle contained its `password` value. The C2-active PB facade now denies config reads for reserved CIDs and bulk `persist`, while allowing commercial CID config reads and legacy behavior. This prevents the ordinary PB management credential from reading the protected connector's password through that method. It does not prove a target credential policy, target operator role, or actual upstream identity.
